SteamPipe Studio is now something you install once and that keeps itself up to date.
Until 1.2.0 every version was a zip to unpack by hand, and it needed the .NET runtime
installed separately. From 1.3.0 there is an installer and a portable version for every
platform, nothing else to install, and the app tells you when a new version is out and
updates itself on request.

## New

### Installer and portable version

- **Windows installer** (`SteamPipeStudio-win-Setup.exe`). Installs for your user only,
  without administrator rights, into `%LocalAppData%\SteamPipeStudio`, with Start-menu and
  desktop shortcuts. Uninstall it from *Settings → Apps*. Your projects and saved passwords
  stay in `%AppData%\SteamPipeStudio` and survive an uninstall.
- **Windows portable** (`SteamPipeStudio-win-Portable.zip`). Unzip it anywhere and start
  `SteamPipe Studio.exe`. It keeps its projects and settings in a `data` folder next to
  itself, so the whole folder can live on a USB stick. The first time it starts it copies in
  the projects already on the machine; saved passwords and the publisher API key are not
  copied, on purpose — enter them again in the portable copy.
- **macOS** — a `.pkg` installer and a portable `.zip` with the app, for Apple silicon and
  for Intel.
- **Linux** — an AppImage: `chmod +x SteamPipeStudio.AppImage`, then run it.
- **No .NET to install.** Every package carries its own runtime, which is why they are
  about 50 MB instead of the 10 MB of the old archives.

### Automatic updates

- When the app starts it checks this repository for a newer release and, if there is one,
  shows **Install X and restart** in the status bar and under *Settings → Updates*.
- Nothing installs on its own. The update downloads when you click, and only what changed
  between versions.
- Before restarting, the app saves every open project.
- An update cannot start while `steamcmd` is running, so it never interrupts an upload or
  a download.
- *Settings → Updates* shows the version you are running, checks on demand, opens the
  releases page, and lets you turn off the check at startup.

## Improved

- **Typing a Steam account is instant on macOS and Linux.** The app used to ask the secret
  store whether a password was saved on every keystroke, which started a process each time
  on those systems. It now asks once, when you stop typing.
- **Faster *Preview contents* on large builds**, especially on network drives: file sizes
  come from the folder listing instead of a second lookup per file, and a content folder
  shared by several depots is read once.
- **Faster startup.** The app no longer reads the publisher API key from the secret store
  just to start.
- **Linux without a keyring:** the encrypted-file fallback derives its key once per run
  instead of on every read.
- **One rule for the default branch.** The build script, the Download button and *Set
  selected build live* each decided on their own which branch is the default one; they now
  share a single rule, which accepts both `public` and `default`.
- **No pause on the first line of `steamcmd` output.** The patterns that read it are now
  compiled when the app is built rather than when the first upload starts.

## Security

- **macOS: passwords no longer pass through a command line.** Saving a Steam password or
  the publisher API key ran Apple's `security` tool with the secret as an argument, where
  any other program on the Mac could read it in the process list while the tool ran. The app
  now talks to the keychain directly, and a failed save is reported instead of silently
  looking like a success.

## Upgrading from 1.2.0 or earlier

- Earlier versions have no updater, so this one has to be installed by hand once. Download
  the installer or the portable version below. The installer finds your existing projects
  and settings; the portable version copies them in the first time it starts. From then on,
  new versions arrive through the app.
- **On macOS**, open the Project tab and save your Steam password again (*Remove*, then
  *Save*), and do the same for the publisher API key in Settings. Items saved by earlier
  versions were created by Apple's `security` tool and most likely still let that tool
  read them without asking — which any program running as you could use. Removing and
  saving them again from 1.3.0 recreates them for SteamPipe Studio alone.

## Known issues

- **The packages are not code-signed yet.** The first time, Windows SmartScreen shows
  "Windows protected your PC": choose *More info → Run anyway*. macOS refuses software from
  an unidentified developer: Control-click the package or the app and choose *Open*, or
  allow it under *System Settings → Privacy & Security*.
- **The macOS packages and the new keychain code have not been tried on a real Mac yet.**
  If something does not work there, please open an issue with your macOS version and chip.
- **A portable copy's first update downloads the full package** (about 50 MB), because the
  portable archive does not include the package updates are calculated from. Later updates,
  and every update of an installed copy, download only the differences.

## For contributors

- Bindings in the XAML are compiled: a mistyped property name is now a build error.
- The installer, portable archive and update packages are made by
  [Velopack](https://velopack.io) in the release workflow. Set `STEAMPIPESTUDIO_UPDATE_FEED`
  to a folder of packages to try an update end to end before publishing; the README
  explains how.
- Release notes now live in `docs/release-notes/<tag>.md` and are required: the release
  workflow stops if the tag has none.
- Dead code removed, duplicated logic merged, the test suite is at 202 assertions.
