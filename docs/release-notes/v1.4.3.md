Two small changes to how the window behaves: Settings no longer leaves a project
half-selected, and the app reopens the project you were working on.

## Changed

### Settings and the project list

- Opening **Settings** now deselects the project in the list. Before, the project stayed
  highlighted while Settings was open, so clicking it did nothing, and getting back meant
  clicking Settings again or another project first.
- To leave Settings, click any project in the list, the one you had open included, and
  it opens. *Close*, or clicking *Settings* again, reopens the project that was open.
- While Settings is open, *Duplicate* and *Delete* are disabled, because no project is
  selected.

### The app reopens your last project

- When the app starts, it opens the project that was open when you closed it, instead of
  the first one in alphabetical order. If you closed it with Settings open, it opens the
  project you had before Settings.
- If that project has been deleted in the meantime, the app opens the first one, as
  before.

## Upgrading from 1.4.2 or earlier

- Installed and portable copies of 1.3.0 and later offer this version in the status bar
  and in Settings, under *Updates*. Your projects, saved passwords and API keys carry over
  unchanged.
- The first time 1.4.3 starts, it opens the first project, because earlier versions did
  not record which one was open. From the next start on, it reopens your last project.
- Coming from 1.4.1 or earlier, read the
  [1.4.2 notes](https://github.com/Andrea332/SteamPipe-Studio/releases/tag/v1.4.2) too:
  uploads that time out on Steam's side now start again by themselves, and failed builds
  show their real reason.
- Coming from 1.2.0 or earlier? Those versions have no updater, so install this one by
  hand once from the files below.

## Known issues

- **Running 1.4.2 or earlier against the same data forgets the last project.** Those
  versions rewrite the settings file without the entry 1.4.3 adds, so after one of them has
  run, 1.4.3 opens the first project once more. This only matters if two versions share one
  machine, for example an installed copy and a portable one that has not updated yet.
- **The automatic upload retry from 1.4.2 has not yet been seen running.** No upload has
  timed out since it was added. It has been checked against the logs of two uploads that
  failed that way.
- **The exported GitHub Actions workflow does not retry.** It runs `steamcmd` itself, so a
  timeout there still fails the job; run it again.
- **A project's own Web API key has still not been tried against Steam with keys from two
  different partners.** If a project's own key is not picked up, please open an issue.
- **The packages are not code-signed yet.** The first time, Windows SmartScreen shows
  "Windows protected your PC": choose *More info → Run anyway*. macOS refuses software from
  an unidentified developer: Control-click the package or the app and choose *Open*, or
  allow it under *System Settings → Privacy & Security*.
- **The macOS packages have not been tried on a real Mac yet.** If something does not work
  there, please open an issue with your macOS version and chip.
- **A portable copy's first update downloads the full package** (about 50 MB), because the
  portable archive does not include the package that updates are calculated from. Later
  updates, and every update of an installed copy, download only the differences.

## For contributors

- `AppSettings.LastProjectId` holds the project to reopen. It is written with the other
  settings when the window closes.
