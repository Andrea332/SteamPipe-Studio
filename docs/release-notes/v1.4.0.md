SteamPipe Studio 1.4.0 makes the window explain itself and adds two things people kept
asking for. Every control now has a tooltip, and an "i" shows where to find it. The
Steam password can be checked before it is saved. And a project can have its own
publisher Web API key, for studios that publish games under more than one Steamworks
partner.

## New

### A Web API key per project

- The Builds tab needs a publisher Web API key to read build history, set builds live and
  download builds. A key only works for the apps of the Steamworks partner it belongs to.
  With a single key in Settings, *Refresh from Steam* answered with a 403 for any project
  whose game another partner publishes.
- The Project tab now has a **Web API key** field. A key saved there is used for that
  project instead of the one in Settings. Projects without a key of their own keep using
  the one in Settings.
- The line under the field says which key the project uses:
  - *Saved for this project*, in green, when it has its own key;
  - *Not saved: uses the key in Settings*, when it borrows the global one;
  - a red warning when there is no key in either place.
- The key goes to the same secret store as the password (DPAPI on Windows, the login
  keychain on macOS, the keyring on Linux) and never into the project file. *Duplicate*
  copies it to the new project, and *Delete* removes it with the project.
- When Steam rejects a key (401 or 403), the message now says whether it was the project's
  own key or the one in Settings.

### Check a password before saving it

- **Check**, next to the password field, signs in to Steam with the password typed in the
  field and signs straight out again. This lets you try a new password before saving it.
  The result appears under the field: *Correct* in green, *Wrong* in red, or *Not checked*
  in yellow.
- *Not checked* happens because `steamcmd` remembers its last login. While that login is
  still valid, Steam does not ask for a password at all, so no password, right or wrong,
  can be tested. The check works again once Steam asks for the password.
- Check is available only once a password is typed in the field, and not while `steamcmd`
  is busy. If Steam Guard wants a code, it asks for it just as during an upload. The
  sign-in is logged on the Upload tab.

### Help where you need it

- Every button, field, checkbox and list now has a tooltip. A small circled **i** next to
  labels, card titles and checkboxes shows where an explanation is.
- Disabled buttons show their tooltip too, and it says when they become available.
- The lines of explanation that used to sit under the fields are gone, so the forms are
  shorter.

### Settings is always one click away

- Settings is no longer a tab. It is a button at the bottom of the project list, and it
  opens in place of the project tabs.
- It now opens even when there is no project yet. Before, it was hidden along with the
  tabs.
- To go back, click a project in the list or *Close*.

## Improved

- **The two folders have clearer names.**
  - *Content folder* is now **App/Game build folder**: the built game, exactly as players
    should get it.
  - *Build output* is now **Upload logs/VDF folder**: `steamcmd`'s logs, the generated
    `.vdf` scripts and the chunk cache.

  These are the same settings under new names, so there is nothing to change in your
  projects. The validation messages use the new names too.
- **A tidier project list.** *New project* and *Import app_build.vdf…* are at the top, and
  *Duplicate* and *Delete* are under the list. Duplicate and Delete are enabled only while
  a project is selected.
- **No more empty tabs.** With no projects, the window explains how to create or import
  one. With none selected, it asks you to pick one.
- **Saved or not, at a glance.** The password, the project's Web API key and the key in
  Settings each show *Saved* in green or *Not saved* in red. The placeholder in each empty
  field says what typing there will do. *Remove* is enabled only when there is something
  to remove.

## Upgrading from 1.3.0

- Copies installed or unzipped from 1.3.0 offer this version in the status bar and under
  *Settings → Updates*. Your projects, saved passwords and API key carry over unchanged.
- If one of your projects belongs to a different Steamworks partner than the key in
  Settings, paste that partner's key into the project's **Web API key** field on the
  Project tab.
- Coming from 1.2.0 or earlier? Those versions have no updater, so install this one by
  hand once from the files below. The
  [1.3.0 notes](https://github.com/Andrea332/SteamPipe-Studio/releases/tag/v1.3.0) explain
  what to do on macOS.

## Known issues

- **Check can only tell a right password from a wrong one when Steam asks for it.** While
  `steamcmd`'s last login is still valid, the answer is *Not checked*.
- **The project Web API key has not yet been tried against Steam with keys from two
  different partners.** The test suite covers which key is chosen, and the window was checked
  visually, but no Steam call was made with a project's own key before this release. If a project's
  own key is not picked up, please open an issue.
- **The packages are not code-signed yet.** The first time, Windows SmartScreen shows
  "Windows protected your PC": choose *More info → Run anyway*. macOS refuses software from
  an unidentified developer: Control-click the package or the app and choose *Open*, or
  allow it under *System Settings → Privacy & Security*.
- **The macOS packages have not been tried on a real Mac yet.** If something does not work
  there, please open an issue with your macOS version and chip.
- **A portable copy's first update downloads the full package** (about 50 MB), because the
  portable archive does not include the package that updates are calculated from. Later
  updates, and every update of an installed copy, download only the differences.

## For contributors

- The README screenshot is drawn from the app itself whenever a release is published
  (`.github/workflows/screenshot.yml`), using placeholder projects. Its secrets are held in
  memory, so running the generator locally never touches your keychain or keyring.
- `MainWindowViewModel` takes an optional `ISecretStore` for that purpose.
- A project's key is filed under `SecretStoreFactory.ProjectApiKey(projectId)`, and
  `SecretStoreFactory.ResolvePublisherKey` decides between it and the global one.
- The test suite is at 217 assertions.
