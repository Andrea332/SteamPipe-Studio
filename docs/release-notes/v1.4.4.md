A small change to the Upload tab: the buttons that act on the log now sit under it, and
*Cancel* turns red while there is something to stop.

## Changed

### The Upload tab

- **Open build log**, **Copy log** and **Clear log** have moved under the log panel, to its
  bottom left. The row above the log now holds only the buttons that start and stop a run:
  *Preview contents*, *Upload build* and *Cancel*.
- **Cancel is red while it can stop something**, that is while `steamcmd` is uploading,
  downloading or checking a password. It turns a lighter red under the pointer and a
  darker one when pressed. When nothing is running it stays the grey of the other disabled
  buttons. The red works in both the dark and the light theme.

## Upgrading from 1.4.3 or earlier

- Installed and portable copies of 1.3.0 and later offer this version in the status bar
  and in Settings, under *Updates*. Your projects, saved passwords and API keys carry over
  unchanged.
- Coming from 1.4.2 or earlier, read the
  [1.4.3 notes](https://github.com/Andrea332/SteamPipe-Studio/releases/tag/v1.4.3) too: the
  app now reopens the project you last had open, and Settings deselects the project while
  it is open. The first start after updating from 1.4.2 or earlier still opens the first
  project, because those versions did not record which one was open.
- Coming from 1.4.1 or earlier, the
  [1.4.2 notes](https://github.com/Andrea332/SteamPipe-Studio/releases/tag/v1.4.2) describe
  the automatic retry of uploads that time out on Steam's side.
- Coming from 1.2.0 or earlier? Those versions have no updater, so install this one by
  hand once from the files below.

## Known issues

- **The red Cancel was checked with a simulated run.** Its colours were checked by drawing
  the window with the Upload tab in the running state, in both themes and under the
  pointer. No real upload has run with this version yet.
- **The automatic upload retry from 1.4.2 has not yet been seen running.** No upload has
  timed out since it was added. It has been checked against the logs of two uploads that
  failed that way.
- **The exported GitHub Actions workflow does not retry.** It runs `steamcmd` itself, so a
  timeout there still fails the job; run it again.
- **A project's own Web API key has still not been tried against Steam with keys from two
  different partners.** If a project's own key is not picked up, please open an issue.
- **The packages are not code-signed yet.** The first time, Windows SmartScreen shows
  "Windows protected your PC": choose *More info → Run anyway*. macOS refuses software from
  an unidentified developer: Control-click the package or the app and choose *Open*, or
  allow it under *System Settings → Privacy & Security*.
- **The macOS packages have not been tried on a real Mac yet.** If something does not work
  there, please open an issue with your macOS version and chip.
- **A portable copy's first update downloads the full package** (about 50 MB), because the
  portable archive does not include the package that updates are calculated from. Later
  updates, and every update of an installed copy, download only the differences.
